# ADR-0002：cut-cell 网格全自研

- 状态：cut-cell 网格全部自研，已定；是否完全不用 AMReX，提议中
- 日期：2026-11-16
- 编号：D2

## 背景

产品需要接近工业电子散热软件中 SmartCells 一类的 cut-cell：一个笛卡尔单元内可以有多个流体或固体控制体，并能处理薄壁、窄缝和多材料共轭传热。对 AMReX EB 的调研表明，它只支持单值切割（每单元一个切割面），没有多材料和固体侧求解，薄壁、窄缝和尖角会被吃掉，因此做不到工业电子散热软件中 SmartCells 一类的 cut-cell。若干备选网格库又是 GPL，与 ADR-0001 冲突。另外 AMReX 没有 Kokkos 后端，若同时用作求解底座，会在 GPU 上引入两套编程模型和内存管理。

Zhiwei 决定网格走全自研，并表示实现可以参考 AMReX。架构组建议：完全不把 AMReX 列为依赖，网格底座在 Kokkos 与 MPI 上自行实现；MVP 只做均匀网格或静态加密，动态 AMR 推到后续版本。是否将“完全不用 AMReX”升为最终决定，仍为提议中。

## 决策

1. `CutCellMesh` 从第一天起按“一个单元含多个控制体”定义，每个控制体带有 region、material 和 body 编号。
2. 网格与并行底座在 Kokkos 和 MPI 上自研，设备内存统一交给 Kokkos 管理。
3. MVP 只实现均匀网格或静态加密；动态 AMR、幽灵层与负载均衡的完整方案后置。
4. 当前仓库不引入 AMReX 作为依赖。实现可以参考 AMReX 等公开资料，但网格接口保持自研抽象，以便日后若调整底座也不必改动求解器边界。“完全不用 AMReX”这一条仍为提议中。

## 后果

- 自研范围扩大，包括以后的幽灵层交换、负载均衡和 AMR。
- 通过网格抽象层和自动验收测试控制风险；写代码不再是主要瓶颈，数值正确性和调试才是。
- 翘曲主线使用分层六面体有限元网格，受该决策的影响有限。
